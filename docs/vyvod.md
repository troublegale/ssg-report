# Вывод

## Предметная область

Мой семестровый проект — [research-graph](https://github.com/troublegale/research-graph): Python-пакет для сбора данных
из внешних API (GitHub API и др.), их обработки и анализа. Публиковать нужно три вида материалов:
документацию пакета (из docstrings), отчёты по лабораторным и результаты анализа данных — таблицы, графики,
формулы метрик, которые пересчитываются при обновлении данных.

## Рекомендуемый стек

| Слой | Выбор | Почему |
|---|---|---|
| Генератор для результатов анализа | **Sphinx + MyST-NB** (ноутбуки исполняются при сборке, `jupyter-cache`) | лучший балл в [T1](t1.md) (88,7): сквозные ссылки на формулы и рисунки, BibTeX, `autodoc` для пакета, русский поиск Snowball |
| Генератор для отчётов и документации без вычислений | **MkDocs Material** + `mkdocstrings` (как этот сайт) | быстрее и проще в CI, переопределение шаблонов, `mike` для версий; только с точными версиями (`mkdocs<2`) и планом перехода на Zensical |
| Зависимости | `uv` + `uv.lock`, `uv sync --locked` в CI | воспроизводимость на чистом раннере |
| Внешние ресурсы | всё локально: шрифты, MathJax, кэш privacy-плагина в репозитории, проверка `check_no_external.py` | сайт работает без CDN, сборка не зависит от сети ([E6](otladka.md#e6), [E7](otladka.md#e7)) |
| CI | GitHub Actions, стадии `lint → build → deploy`, actions закреплены по SHA | |
| Основная площадка | **GitHub Pages** через `upload-pages-artifact` + `deploy-pages` | быстрее, нет прав на запись в код у job публикации |
| Отечественная площадка | **Helios** через [`helios-deploy-action`](challenge.md): атомарные релизы, healthcheck, превью, откат | см. [P4](p4.md#sravnenie) |

## Когда рекомендация меняется

1. **Нужна PDF/DOCX-версия статьи или цитирование по ГОСТ (CSL)** → Quarto вместо Sphinx (лучший по научной разметке в T1),
   ценой медленной сборки и внешнего бинарника в CI.
2. **Вычисления тяжелее лимитов CI** (часы счёта, GPU, большие данные) → вычисления выполняются отдельно, CI собирает сайт
   из готовых артефактов; исполнение ноутбуков при сборке выключается (`nb_execution_mode: off` / Quarto `freeze`).
3. **Сайт должен быть доступен только на отечественной площадке** (требования организации или недоступность GitHub) →
   GitHub Pages исключается, CI переносится на GitVerse/SourceCraft; `helios-deploy-action` — обычный bash-скрипт и
   переносится в любой CI с SSH.
4. **Нельзя хранить на CI ключ с полным shell** → Helios не подходит в описанном виде (у студента одна учётная запись);
   нужен хостинг с отдельными правами на загрузку (объектное хранилище S3 с ключом только на bucket, SFTP-only аккаунт).
5. **Новый долгоживущий проект документации** → вместо MkDocs 1.x оценить Zensical: ядро MkDocs заморожено, Material в
   режиме поддержки до мая 2027 г.

## Ограничения сделанного

- deploy-ключ на Helios даёт полный shell учётной записи — ограничить его `command=`-опциями нельзя без потери атомарного
  переключения ([P4](p4.md#deploy-ключ-и-проверка-хоста));
- Helios — единственный сервер без CDN; защита от перебора может заблокировать IP раннера так же, как заблокировала мой
  ([E2](otladka.md#e2)) — на этот случай есть `healthcheck-from: remote`, но не саму доставку;
- MathJax 3.2.2 и шрифты обновляются вручную, так как лежат в репозитории.
